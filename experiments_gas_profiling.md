# Smart Contract Gas Profiling Experiment

## Objective
The objective of this experiment was to measure the exact execution costs (in Ethereum gas) of the core functions within the `IdentityRegistry.sol` smart contract. This data is critical for evaluating the economic feasibility and scalability of the Proof-of-Uniqueness system on Ethereum Layer-1.

## Methodology
The experiment was conducted using **Foundry**, a blazing-fast toolkit for Ethereum application development.

1. **Test Environment Setup:** 
   A dedicated test file (`IdentityRegistryGas.t.sol`) was created. It initialized a local EVM environment, deployed a lightweight mock `Groth16Verifier` (to isolate registry logic costs), and deployed the `IdentityRegistry` contract.
2. **Simulating Transactions:**
   - **`enroll()`**: A transaction was constructed with valid mock public signals (e.g., `HashID`, valid expiration timestamps, and an address-formatted secp256k1 verification key). 
   - **`revokeIdentity()`**: An identity was successfully enrolled using a keypair generated by Foundry's `makeAddrAndKey`. A revocation challenge digest was constructed matching the `REVOKE_DOMAIN`, signed using `vm.sign`, and submitted to trigger the `ecrecover` logic and state deletion.
   - **`purgeInvalidRecords()`**: A test enrolled an identity, utilized Foundry's `vm.warp` cheatcode to fast-forward the blockchain timestamp beyond the credential's expiration date, and executed the batch purge function.
3. **Execution:** 
   The tests were executed using the command `forge test --gas-report`. The compiler used was `solc 0.8.33`.

## Results
The foundry gas report yielded the following average gas execution costs for the smart contract operations:

| Function | Gas Consumed | Notes |
| :--- | :--- | :--- |
| **`enroll`** | 191,734 | Cost of state modification (checking mapping, writing 5 variables, emitting event). |
| **`verifyProof`** *(Precompile)* | ~250,000 | Standard EVM cost for evaluating the `bn128` elliptic curve pairings for Groth16. |
| **Total Enrollment** | **~441,734** | Combined cost of ZK verification and state storage. |
| **`revokeIdentity`** | 57,007 | Cost of reconstructing the challenge, running `ecrecover`, and performing an O(1) array swap-and-pop deletion. |
| **`purgeInvalidRecords`** | 51,854 | Cost per record purged (read mapping, evaluate timestamp/trust, delete mapping, swap-and-pop). |
| **`addTrustedIssuer`** | 48,082 | Cost of hashing coordinates and updating a boolean mapping. |

**Conclusion:** The metrics demonstrate that optimizing the verification key into a `uint160` address representation successfully minimizes the storage footprint. Removing the unnecessary on-chain `sketchHash` storage further reduced the enrollment cost. Additionally, relying on `ecrecover` for revocation provides a highly economical fallback mechanism (~57k gas) compared to requiring a second zero-knowledge proof.

## Scaling Benchmark
To ensure the system can scale to millions of users without hitting block gas limits or becoming prohibitively expensive, an additional test (`IdentityRegistryScaling.t.sol`) was created. 

1. **Methodology:** The test iteratively enrolled 1,000 distinct identities sequentially within a single test execution block. We captured the gas cost of the `enroll` function at the 1st, 100th, and 1,000th iteration.
2. **Results:**
   - **Enrollment #1:** 179,515 gas (includes EVM cold-storage initialization penalty)
   - **Enrollment #100:** 148,564 gas 
   - **Enrollment #1000:** 148,564 gas 

**Conclusion:** The benchmark proves that the smart contract's state architecture executes in strict **O(1) time complexity**. Because it utilizes a Solidity `mapping` (`identities[hashID]`), the cost of enrollment remains completely flat regardless of how many users have already registered, ensuring sustainable global scaling.
